# Task Plan Companion (macOS prototype)

Native SwiftUI/AppKit UI fed by real Task Plan MCP mutations. No iframe, HTTP port or state polling.

Build: `sh build.sh` in this directory. Open `build/Task Plan Companion.app`, or enable `TASK_PLAN_COMPANION_AUTOSTART=1` in the MCP environment (enabled in this local installation). A newly committed root plan launches the app if its socket is absent/refused. Updates, completion, reads and retry deliveries never launch it. No macOS login item is installed. The app holds a kernel file lock so simultaneous MCP creators cannot start two owners. `TASK_PLAN_COMPANION_BINARY` can override the built executable path.

Default state: `~/.codex/task-plan/companion/state.json`; private Unix socket: `~/.codex/task-plan/companion/control.sock`. `CODEX_HOME`, `PLAN_COMPANION_DATA` and `PLAN_COMPANION_SOCKET` override these defaults. MCP uses `TASK_PLAN_COMPANION_SOCKET`; without it the original inline mode remains available.

The persisted focus-collapse preference is controlled by the private MCP tool `set_companion_focus_mode`. When enabled, leaving Codex collapses the window into a draggable translucent plan icon with its own saved position; focusing Codex restores the saved expanded frame. Hovering the icon expands the window after a short delay and clamps it to the current screen. `PLAN_COMPANION_FOCUS_COLLAPSE=1` supplies the initial default only when the saved preference is absent.

New root plans select themselves, and a plan that transitions to completed becomes active immediately so its completion is visible. Ordinary updates, cancellation and replay do not select another plan. Every plan receives a stable pseudo-random icon from a pool of 150 emoji. The icon has no permanent circle; its small `+N` badge shows how many other plans are open. Hovering immediately starts the spring reveal and adds one shared rounded background beneath the complete icon tray. Each alternative has a detached non-activating Codex-dark floating-card tooltip with an 11-point, two-line word-wrapped title; it may extend outside the companion window, is clamped to the visible screen, and does not intercept clicks. The hover state includes the tooltip bridge and a 180 ms exit grace. On leave, the tooltip fades, icons spring back, then the shared tray fades instead of disappearing abruptly. Clicking an alternative switches plans. There is no menu selector. Linked children update the root, without separate switcher entries. The app does not infer the selected Codex thread. The non-activating panel accepts clicks without stealing focus or hiding itself, and it never activates itself on a plan event. The prototype currently has no menu bar item or close control; that lifecycle UX is intentionally deferred.

The companion uses Codex panel colors (`#222224` surface, `#303032` border and `#B8B8BA` unfinished-step text) inside a borderless rounded window with the system window shadow disabled, so only the exact custom border is rendered. The compact header contains only the plan icon, title and a baseline-aligned counter in a thin rounded capsule, followed by an inset 0.5-point `#303032` divider. Header and rows share one 12/24/8-point grid: 12-point outer/top inset, an 18-point emoji glyph centered without changing its 24-point layout column, then an 8-point gap to the common title/step/note text edge. Long plan titles wrap while the fixed-size counter stays on the first text baseline. Drag any noninteractive content to move the window; the icon switcher and inner 18-point resize edges keep priority. Resizing is implemented by the content view instead of AppKit's competing native `.resizable` layer, so one functional cursor owns each edge and the inner/outer transition returns to the normal pointer. The hosting view's flipped coordinates are explicitly mapped back to physical top/bottom edges. The default size is 420×430 points and the minimum is 280×240; overflowing steps scroll inside the window. Expanded position/size and collapsed-icon position are persisted separately in the companion's private `state.json` and restored when their frames still intersect a connected display. Pending steps use three subtly brighter dim dots whose bottom edge follows the first-line text baseline; each step has a stable random 3.0–5.399 second bounce interval. A step whose next progress requires the user's answer uses the distinct `waiting_for_user` state: a backgroundless system-orange `questionmark.bubble` with a quiet breathe-and-lift animation; `blocked` remains reserved for failures and non-user obstacles. Other left status marks are backgroundless and use the original vivid system status palette. Rows have 3-point vertical padding and no stack gap. The active step has no card highlight. Its 3-point muted Codex-blue progress bar is limited to the rendered title width and sends the highlight from the leading edge of the filled segment. Step hints sit 3 points below the head and blur/fade/rise when first shown or changed. Subagent icons never reserve title width: when the title-plus-icons combination overflows, the icons overlap one another in a compact stack above the trailing text, while a regular-material veil plus surface fade blurs and softens only the text beneath them. Any overflow with two or more icons compacts them to a 0.42-width overlap stride. Icons retain the ten illustrated category assets, seeded motion and subtle opacity/contrast pulse. Completed agents are static and carry a small Codex-green checkmark without a badge background. The checkmark plays one short pop-and-settle animation when completion appears, then gives a calm periodic rock and lift; Reduce Motion keeps it, the pending dots and the question icon static. Completed plan icons get their own green pop animation over a material-blurred badge that dissolves as the check settles. In focus-collapse mode a completed or cancelled plan starts its 30-second retention only when Codex next receives focus or the icon expands on hover; with that mode disabled, the legacy timer starts at `completedAt`. `PLAN_COMPANION_RETENTION_SECONDS` exists only to shorten this interval in isolated tests. The footer is omitted.

Mutations and coalesced outbox records commit atomically in `plans.sqlite`. Senders retry only pending deliveries, with a capped backoff; when caught up, there is no polling timer. The receiver persists before ACK. Repeated/older events are successful no-ops. Multiple MCP processes share the outbox. Restarting a sender drains persisted pending events. The app safely recovers its own stale socket after a crash. No old plan history is imported automatically.

The normal Codex goal adapter remains read-only. Goal pause changes are observed on the next applicable MCP call, not pushed immediately by Codex. This integration does not provide new goal hooks. Worker name/category/status are preserved and rendered with the bundled illustrated category icon pack.

`scripts/companion-smoke.mjs` runs the real MCP plus a hidden native app using an isolated database/socket. `scripts/companion-cursor-live-smoke.mjs` verifies horizontal, top and bottom resize plus both cursor transitions; `scripts/companion-header-live-smoke.mjs` physically checks immediate reveal, wrapped detached tooltip, staged exit and selection; `scripts/companion-animation-smoke.mjs` verifies pending dots, the question state, new/changed hints and the completed-agent check; and `scripts/companion-layout-smoke.mjs` renders the minimum-width layout. Set `COMPANION_BINARY` to the built executable. Tests write reports and renders into temporary fixture directories. They do not touch production plans.
